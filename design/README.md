# Handoff: Diary — 自作入試数学問題サイト デザイン一式

## Overview

`yu531deve/diary`（自作の大学入試数学問題を Web と PDF で公開する静的サイト）のビジュアルデザイン一式。
コンテンツ層（`content/`, `fields.yaml`, `tags.yaml`, 静的サイトジェネレータ）はすでに実装済みという前提で、**このバンドルは「見た目と体験」だけを定義する**。

デザインコンセプトは Active Theory 系の没入型スクロールテリング。トップページはスクロール量に駆動されるパーティクル演出で、`Diary` の文字 → 問題0001のグラフ → `1000+` → 上方拡散、と 4 シーンを連続変形する。下層ページはその世界観を落ち着かせた、余白と細い罫線でできたダークな情報設計。PDF だけは真逆に振り、白地・明朝・ハッチングの「紙」として設計している。

---

## About the Design Files

同梱の HTML は **デザインリファレンス（プロトタイプ）** であり、そのまま本番に載せるコードではない。
意図した見た目・動き・状態遷移を確認するためのもの。

**やってほしいこと**: これらの HTML デザインを、既存リポジトリの環境（静的サイトジェネレータ + 素の HTML/CSS/JS）で作り直すこと。
既存の `site/CLAUDE.md` にある規約（重い JS 禁止・装飾アニメ禁止など）と衝突する場合は、**規約側を見直すか、演出をトップページだけに限定する**方針で相談してほしい（オーナーは「デザイン案は自由に、実装時に調整する」と合意済み）。

各ファイルは `<x-dc>` というカスタム要素と `support.js` ランタイムに依存したプレビュー形式になっている。**このランタイムは移植しないこと。** テンプレート部分の DOM 構造とインラインスタイル、`<script data-dc-script>` 内のロジッククラス（canvas 描画とアニメーションの実装）だけを読み取って、素の HTML/CSS/JS に書き直す。

ブラウザで直接開けば動作を確認できる（`support.js` を同じフォルダに置いたまま開くこと）。

## Fidelity

**High-fidelity**。色・タイポグラフィ・余白・インタラクションはすべて確定値。ピクセル単位で再現してよい。
唯一の例外は問題文・解答文などのコピーで、これは実データ（`content/0001/`）に差し替わる前提のサンプル。

**タイポの規則**

- 本文の行間は `1.9`〜`2.1`。数式が混ざる行は `2.05` 以上。
- インライン数式は本文より 1px 大きい STIX Two Text italic にして、和文の中で浮かせる。

- セクション間の縦: `44〜64px`

- **border-radius**: ほぼ `0`。ボタンだけ `2px`（デスクトップ）/ `3px`（モバイル）、チップとピルは `999px`、モバイル端末枠は `34px`。**角丸を多用しないのがこのデザインの肝。**

## Screens / Views

### 1. トップページ（`01_top_scroll.dc.html`）

**Purpose**: サイトの第一印象。スクロールするだけで「自作の入試数学を大量に作っている場所」だと伝える。

**Layout**
- `#track` = `height: 560vh` の縦長トラック。その中に `position: sticky; top: 0; height: 100vh` の固定ステージ。
- ステージ内は全面 `<canvas>`（`position:absolute; inset:0`）+ その上に絶対配置のキャプション 4 枚。
- ステージ通過後、通常フローで「分野」セクション → 「新着」セクション → フッター。

**進捗の取り方**
```js
const r = track.getBoundingClientRect();
const p = clamp(-r.top / (r.height - window.innerHeight), 0, 1); // 0→1
```

**パーティクル演出（中核）**

5 つのターゲット座標セットを用意し、進捗 `p` に応じて補間する。全パーティクルは常に同一個数（各セットの最大要素数 `N` に合わせて短いセットは繰り返しで埋める）。

| セット | 内容 | 生成方法 |
|---|---|---|
| 0 | ランダム散乱 | `Math.random()` で画面全体 |
| 1 | 文字 `Diary` | オフスクリーン canvas に `700 min(w*0.24, 340)px Space Grotesk` で描画 → `getImageData` の alpha>128 を 6px グリッドでサンプリング |
| 2 | 問題0001のグラフ | `y = x²`（0.018 刻み）、`y = x + 2`（0.026 刻み）、y 軸（0.09 刻み）、x 軸（0.07 刻み）の点列 |
| 3 | 文字 `1000+` | セット 1 と同じ手法、`min(w*0.22, 300)px` |
| 4 | 上方へ拡散 | ランダム x、`y = random*h - h*0.8` |

**セグメント表**（`p` → `[fromSet, toSet, localT]`、`localT` は smoothstep `t*t*(3-2t)` 適用）

| p の範囲 | from | to |
|---|---|---|
| 0.00 – 0.14 | 0 | 1 |
| 0.14 – 0.26 | 1 | 1（静止） |
| 0.26 – 0.42 | 1 | 2 |
| 0.42 – 0.56 | 2 | 2（静止） |
| 0.56 – 0.70 | 2 | 3 |
| 0.70 – 0.80 | 3 | 3（静止） |
| 0.80 – 1.00 | 3 | 4 |

**パーティクルの毎フレーム処理**
```js
const tx = a.x + (b.x - a.x) * e;          // e = smoothstepした localT
pt.x += (tx - pt.x) * 0.09 + Math.sin(t*0.001 + pt.ph) * 0.3;   // 追従 + 微振動
// マウス反発（半径 120px、押しのけ強度 5px）
if (d2 < R*R) { pt.x += dx/d * (1 - d/R) * 5; }
```
- 描画は `fillRect(x, y, s, s)`（円ではなく矩形）。サイズ `s` は `1.1〜2.5px` のランダム。
- 16% のパーティクルだけ `rgba(82,224,245,.95)`、残りは `rgba(226,236,244,.78)`。
- **軌跡（トレイル）**: 毎フレーム `clearRect` せず `fillStyle='rgba(5,6,10,0.34)'; fillRect(0,0,w,h)` で半透明に塗る。これが尾を引く見た目の正体。
- グラフ形状（セット 2）が支配的な間だけ、放物線と直線が囲む領域を `rgba(82,224,245,0.13)` で塗る。ウェイトはセット 2 への/からの補間量。
- DPR は `min(devicePixelRatio, 1.5)` に制限（パーティクル数が多いため）。

**キャプション 4 枚**（`opacity` と `translateY` を JS で直接操作。フェード幅は 0.05）

| id | 表示区間 | 位置 | 内容 |
|---|---|---|---|
| `#c1` | p < 0.13 | 中央下（`top:64vh`） | `ORIGINAL ENTRANCE-EXAM MATHEMATICS` / 「自作の入試数学、1000問へ。解く価値のある一問を。」 / SCROLL インジケータ |
| `#c2` | 0.30 – 0.58 | 左（`left:48px`、縦中央、`max-width:440px`） | `PROBLEM 0001` / 「放物線と<br>囲まれた面積」40px 900 / `∫₋₁² {(x+2) − x²} dx = 9/2` / 説明文 |
| `#c3` | 0.60 – 0.82 | 中央下（`top:66vh`） | `GOAL` / 「1000問を目指して、毎日つくる。」 |
| `#c4` | p > 0.86 | 全面中央 | 「解く価値のある、一問を。」56px 900 / CTA 2 つ |

フェードは `Math.min((p-a)/0.05, 1)` と `Math.min((b-p)/0.05, 1)` の小さい方。`transform: translateY((1-opacity) * 26px)`。

**固定 UI**
- ヘッダー: `position:fixed`, `padding:26px 48px`, 背景 `linear-gradient(180deg, rgba(5,6,10,.85), rgba(5,6,10,0))`
- 右端インジケータ: `01 / 04` のシーン番号（区切りは p = 0.26 / 0.56 / 0.80）+ 高さ 120px の縦バー（`transform: scaleY(p)`）
- 左下: `PROBLEMS 0042 / FIELDS 18 / GOAL 1000+`
- カスタムカーソル: 34px の円（`mix-blend-mode: screen`、`lerp 0.14` で遅延追従）+ 6px の即時ドット

**スクロール後のセクション**
- 分野リスト: 1 行ずつ `border-top: 1px solid rgba(255,255,255,.1)`、分野名 `52px/900`、ホバーで `color:#52e0f5` かつ `padding-left: 26px`（`transition: all .25s`）
- 新着リスト: 番号 / タイトル / タグピル / 難易度ドット5個 / 日付 の 1 行。ホバーで `background: rgba(82,224,245,.04)` + `padding-left:14px`

**モバイルでの扱い**: この演出はそのまま持ち込まない。`03_mobile.dc.html` の軽量版（下記）に差し替える。

- **解答**: 同じ 3 ステップ。ブラーは `8px`、ボタンは `13px`

### 4. ローディング画面（`04_loading.dc.html`）

**Purpose**: 初回訪問時の 3.2 秒。トップの演出と地続きに見せる。

- 全面 `#05060a` のカーテン + canvas。背後にサイトのトップ（ヘッダー・キャッチコピー）が `opacity:0` で待機
- パーティクルは**画面外の円周上**（`半径 = max(w,h) * 0.75 * (0.5〜1.4)` のランダムな角度）から出発し、`Diary` の形へ収束
- 各パーティクルに `delay = random * 0.42` を持たせ、`local = clamp((raw - delay) / (0.62 - delay*0.4), 0, 1)` を smoothstep して補間 → **バラけて集まる**
- `raw > 0.86` から放出フェーズ: `x += (x - w/2) * k² * 1.4`、`y` は同様 + `-k*60`。同時にフェードアウト
- 進捗 0.15〜0.92 の間だけ背景に 5 本の正弦波（`rgba(82,224,245,0.05)`）
- **UI**: 左下に `LOADING PROBLEMS → BUILDING INDEX → READY → WELCOME` のフェーズ表示 + 320px の進捗バー、右下に `000〜100` の 3 桁カウンタ（76px mono）、左上に `DIARY — SELF-MADE MATHEMATICS`
- 100% でカーテンが `opacity 0`（`transition: .9s ease`）、サイトが `opacity 1`（`.8s ease .3s`）で現れる
- 実装時は `sessionStorage` で「初回のみ」にするか、実際のアセット読み込み進捗に結びつけること。プロトタイプは固定時間

### 5. PDF 紙面（`05_pdf_sheets.dc.html`）

A4 縦 2 ページ。**Web とは完全に別のパレット**（白地・明朝・印刷用シアン `#0b6f80`）。

`<doc-page size="a4">` + `<section class="page">` × 2 という構造でプレビューしているが、実装側は既存の PDF 生成パイプライン（LaTeX / TikZ か HTML→PDF）に合わせて作り直す。**紙面の設計値だけ拾えばよい。**

- **余白**: `20mm 18mm 16mm`
- **ヘッダー**: `Diary`（mono 15pt）+ `SELF-MADE MATHEMATICS`（sans 7.5pt, `letter-spacing:.22em`）、右に `問題用紙 — PROBLEM SHEET` / `解答用紙 — SOLUTION`。下に `2px solid #14161a`
- **P.1 問題用紙**
  - 左に問題番号のボックス（`1.5pt` 枠、`NO.` + `0001` 21pt mono）、右にタイトル 20pt/700 とメタ行（分野 / 科目 / 難易度ドット / 目安時間）
  - 本文と図を `grid-template-columns: 1fr 62mm; gap:10mm`
  - 図は `.6pt` 枠 + `FIG. 1` ヘッダー + 52mm 高
  - **解答欄**: 残り高さいっぱいに `repeating-linear-gradient` で 9.9mm 間隔の罫線。書き込み前提
  - フッター: ライセンス表記 + `0001 — P.1 / 2`
- **P.2 解答用紙**
  - 設問ごとに `(1) 交点の x 座標` のようなラベル（sans 8pt `letter-spacing:.18em` `#0b6f80`）
  - 途中式は `background:#f4f6f8`, `padding:3〜4mm 5mm`
  - **答えは `border-left: 2pt solid #0b6f80` + `background:#eef7f9` + 太字**（Web の答えパターンと対応）
  - 末尾に「補足」ボックス（`.6pt` 枠 + `#fbfcfd`）で 1/6 公式の解説
- **図の印刷版**: 塗りつぶしではなく**45° のハッチング**（`rgba(11,111,128,0.4)`, 0.6pt, 6px 間隔）+ `#eef7f9` の下地。軸には矢印、`C` `ℓ` `O` `−1` `2` `S` のラベル。線は黒（`#14161a`）で、色に頼らない
- 印刷時に色が出ない環境を想定し、**シアンは補助的な役割に留め、情報は黒とハッチングで判別できる**ようにしてある

## 実装時の注意

1. **`site/CLAUDE.md` の「重い JS 禁止・装飾アニメ禁止」規約と正面から衝突する。** トップページのパーティクル演出（約 3000 個、60fps）はこの規約の例外扱いにするか、規約自体を更新する必要がある。オーナーと確認すること。
2. **パフォーマンス**: DPR は 1.5 に制限、`fillRect` で描画（`arc` は使わない）、トレイルは半透明塗りで実現。それでも低スペック端末では重い。`particleGap` を 6px → 8px にすると粒子数が約半減する。
3. **モバイルではスクロール演出を使わない。** `03_mobile.dc.html` の静的な収束アニメに差し替える。
4. **数式**: プロトタイプは Unicode（`∫ ₋₁ ² ² α β`）で組んでいるが、本番は KaTeX か MathJax を使うこと。フォントは STIX Two Text 相当を指定する。
5. **アクセシビリティ**: canvas 演出には `aria-hidden="true"` を付け、キャプションのテキストは通常の DOM として読ませる。`prefers-reduced-motion` 対応は必須。
6. 現在の数値（`0042 PROBLEMS` / `18 FIELDS` / 各分野の問題数）はすべてサンプル。ビルド時に実データから生成すること。
