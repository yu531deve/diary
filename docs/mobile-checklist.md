# モバイル実機チェックリスト

Diary サイトのモバイル表示・挙動を実機で確認するためのチェックリスト。issue #125（#111 の子）。
PR のマージ前後に Yu が実機で辿る。対象実装は主に以下:

- `site/src/components/BottomTabNav.astro`（下部タブナビ、`max-width: 860px` で表示）
- `site/src/pages/index.astro`（トップページ: モバイルもデスクトップと同じ `#track` のスクロール駆動演出を使用。#118 で旧 `#mobile-hero` は廃止済み）
- `site/src/pages/problems/[id]/index.astro`（`.mobile-action-bar`: 固定アクションバー）
- `site/src/components/SearchModal.astro`（⌘K 検索モーダル）
- `site/src/lib/save-store.ts`（保存機能、localStorage 任意機能）

対象端末: **iOS Safari** と **Android Chrome** の両方で、下記項目をひととおり実施する。

## 1. 下部タブナビ（BottomTabNav）

- [ ] 画面幅 860px 以下（スマホ）でページ下部にタブ（ホーム/分野/検索/保存の4つ）が表示される
- [ ] iPhone のホームインジケーターがある機種で、タブの下に隙間（safe-area）ができていて、インジケーターとタブのラベルが重ならない・隠れないことを確認する
- [ ] 各タブを指で軽くタップし、狙った位置から多少ズレても反応する（タップ領域が窮屈すぎないこと。実装上は 44px 以上を確保）
- [ ] 「ホーム」タブをタップして `/` に遷移し、アクティブ表示（水色）になっていることを確認する
- [ ] 「分野」タブをタップして `/fields/` に遷移し、アクティブ表示になっていることを確認する
- [ ] 「保存」タブをタップして `/save/` に遷移し、アクティブ表示になっていることを確認する
- [ ] 「検索」タブをタップして⌘K 検索モーダルが開くことを確認する（「2. 検索モーダル」も参照）
- [ ] 各ページをスクロールしても、下部タブが画面下に固定表示されたままであることを確認する

## 2. ⌘K 検索モーダル（SearchModal）のモバイル挙動

- [ ] 下部タブの「検索」ボタン、またはトップページの検索トリガーからモーダルを開く
- [ ] モーダルを開いた瞬間にソフトキーボードが立ち上がり、入力欄にフォーカスが当たっていることを確認する
- [ ] ソフトキーボード表示中も検索結果一覧・フィルタチップ（分野）が隠れずスクロールで見えることを確認する
- [ ] 何文字か入力して結果が絞り込まれることを確認する
- [ ] 結果行をタップして該当の問題ページに遷移することを確認する
- [ ] 「ESC」ボタンまたはオーバーレイのタップでモーダルが閉じ、ソフトキーボードも閉じることを確認する
- [ ] モーダルを閉じた直後、意図せず別の入力欄にフォーカスが移っていないか（背面のページを誤操作しないか）を確認する
- [ ] 横向き（landscape）でモーダルを開き、入力欄・結果一覧・フッターが画面内に収まる／スクロールできることを確認する

## 3. 問題ページの固定アクションバー（`.mobile-action-bar`）

- [ ] 問題ページ（`/problems/{id}/`）を開き、画面下部に「解答を見る」「PDF」「☆保存」の固定バーが表示される
- [ ] 本文をスクロールしても固定バーが問題文・図・ページャの下に隠れず、常に見えていることを確認する
- [ ] 本文最下部（ページャ・関連問題）までスクロールしたとき、固定バーが最後の行に重なって文字を隠していないか確認する
- [ ] iPhone のホームインジケーターがある機種で、バーの下に隙間（safe-area）があり、インジケーターとボタンが重ならないことを確認する
- [ ] 横向き（landscape）で問題ページを開き、固定バーが画面下に正しく表示され、問題文の一部を過剰に覆っていないか確認する
- [ ] 「解答を見る」をタップして解答ページに遷移することを確認する
- [ ] 「PDF」ボタンをタップして問題 PDF がダウンロード（または表示）されることを確認する（「6. PDF ダウンロード」も参照）
- [ ] 「☆」ボタンをタップして保存状態がトグルされる（水色にハイライトされる）ことを確認する（「5. 保存機能」も参照）

## 4. トップページのスクロール駆動演出（`#track`、モバイルもデスクトップと同じ仕組み）

- [ ] トップページ（`/`）を画面幅 860px 以下で開き、デスクトップと同じ `#track` のスクロール駆動パーティクル演出（Diary の文字形 → グラフ → 1000+ → CTA と切り替わる）が表示されることを確認する
- [ ] スクロール量に応じてキャプション・シーンが正しく切り替わり、途中で止まったり飛んだりしないことを確認する
- [ ] 演出中・演出後もページが引っかかりなく操作でき、スクロールがカクつかない（体感 fps が保たれている）ことを確認する（モバイルはパーティクル数・devicePixelRatio を軽量化しているため、特に確認する）
- [ ] 演出を数分表示させたままにして、端末が異常に熱くなっていないか確認する
- [ ] 端末の設定で「動作を減らす」（iOS: 設定 > アクセシビリティ > 動作 > 視差効果を減らす／Android Chrome: OS のアニメーション削減設定）を ON にした状態でトップページを開き、スクロールしても演出が動かず Diary の静止形のみが表示されることを確認する
- [ ] 上記の設定を OFF に戻すと、通常どおりスクロール駆動演出が動くことを確認する

## 5. 保存機能（save-store.ts）と localStorage 無効時の挙動

- [ ] 通常のブラウジングモードで問題ページの「☆」を押して保存し、`/save/` ページに反映されることを確認する
- [ ] 同じ問題の「☆」をもう一度押して解除し、`/save/` から消えることを確認する
- [ ] iOS Safari のプライベートブラウジング（または Android Chrome のシークレットタブ）で問題ページを開き、「☆」ボタンが押せない状態（disabled 表示）になっていることを確認する
- [ ] 上記のプライベートブラウジング環境でも、問題文の閲覧・「解答を見る」・PDF ダウンロード・検索など保存機能以外がすべて問題なく動くことを確認する（エラーで固まらない・白画面にならない）

## 6. PDF ダウンロードリンク

- [ ] 問題ページ側パネルの PDF リンク（「問題（印刷用）」）をタップし、PDF がダウンロードまたは新規タブで開かれることを確認する
- [ ] 解答 PDF リンク（「解答（印刷用）」、存在する場合）も同様に確認する
- [ ] HTML 変換に失敗しフォールバック表示（PDF 埋め込み）になっている問題ページでは、埋め込み PDF が正しく表示され、ピンチズーム・スクロールで読めることを確認する

## 7. 数式（MathML）の表示

- [ ] 数式を含む問題ページを開き、長い数式が画面幅からはみ出さず折り返される、または該当ブロックだけが横スクロールできることを確認する（ページ全体が横スクロールしてしまわないこと）
- [ ] 数式部分をピンチズームしても表示が崩れない（文字が重ならない）ことを確認する

## 8. 横向き（landscape）表示全般

- [ ] トップページ・問題ページ・解答ページ・分野一覧・保存ページを横向きで開き、下部タブ／固定アクションバーが本文の主要部分（見出し・操作ボタンなど）を覆っていないことを確認する
- [ ] 横向きのまま⌘K 検索モーダルを開閉して問題なく操作できることを確認する

## 9. iOS Safari / Android Chrome 共通確認

上記の全項目を、可能な範囲で以下の両方で実施する。

- [ ] iOS Safari で 1〜8 の主要項目（下部タブ・検索モーダル・固定アクションバー・保存・PDF）を一通り確認した
- [ ] Android Chrome で 1〜8 の主要項目（下部タブ・検索モーダル・固定アクションバー・保存・PDF）を一通り確認した
